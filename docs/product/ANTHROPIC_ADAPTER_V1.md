# Adaptateur Anthropic Messages v1

Issue #32, Astra. `AnthropicModel(api_key, *, model="claude-haiku-4-5-20251001", transport=None, timeout=20)` expose `generate(request, *, max_output_tokens=300)` pour DeadlineExtractor. Aucune lecture environnement, aucun réseau au constructeur. Le modèle par défaut est confirmé dans le [primer officiel](https://platform.claude.com/docs/en/claude_api_primer). Le protocole suit [Messages](https://platform.claude.com/docs/en/api/messages/create).

Un seul POST vers `https://api.anthropic.com/v1/messages`, version `2023-06-01`, header `x-api-key`. Pas de retry, redirection, outils ou streaming. Instructions fixes dans system, uniquement request.data sérialisé JSON dans user ; les instructions reçues ne permettent pas de changer le prompt système. Sortie demandée : objet abstain ou proposed du contrat extraction. Maximum 300 tokens, timeout socket positif au plus 20 secondes et limite de réponse 1 MiB. Le timeout est celui des opérations socket, pas une garantie de temps total DNS/réseau.

Port injectable : objet `post(url, *, headers, body, timeout, max_bytes)` retournant `(status:int, body:bytes)`. Le transport standard utilise HTTPS direct, sans proxy implicite, et lit au plus max_bytes+1 octets. Les ports injectés doivent respecter timeout et taille ; l’adaptateur revérifie statut et longueur.

Retour exact `{output:dict, usage:null|{input_tokens:int,output_tokens:int}}`. Une seule section text et stop_reason=end_turn sont acceptés. JSON strict : pas de markdown, clés dupliquées, NaN, texte ajouté, réparation ou fallback. Schéma extraction validé structurellement ; ID connu, preuve et horizon restent contrôlés par DeadlineExtractor. L’usage vient de l’enveloppe fournisseur ; absent vaut null, invalide échoue. Toute panne devient `ModelError` au message fixe, sans texte externe ni chaîne d’exception visible. Repr expurgé.

Tests exclusivement injectés, sans compte. L’adaptateur ne valide ni clé réelle ni facturation. Le budget et le consentement de transmettre un extrait sont à la charge de l’intégration.

Issue #38 : le POST demande désormais les [Structured Outputs officiels](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) via `output_config.format = {type: "json_schema", schema: ...}`. Le schéma fixe utilise `anyOf` pour les deux objets `abstain` et `proposed`, avec les constantes `schema_version`/`status`, tous les champs de chaque branche requis et `additionalProperties: false`. La documentation supporte `anyOf` et `const`, ainsi que Haiku 4.5 ; aucun header bêta n’est nécessaire. Les données du message et des événements ne sont jamais insérées dans le schéma. Les longueurs, preuves, identifiants et instants restent validés localement ; aucun `minLength` ou `maxLength` non supporté n’est transmis.

Le prompt et le parseur strict restent actifs : Markdown, refus, réponse tronquée ou schéma invalide échouent sans réparation ni nouvel appel. Les limites restent 300 tokens et 20 secondes par opération socket. La compilation initiale du schéma peut ajouter de la latence, et le fournisseur ajoute des tokens d’entrée pour le format : aucune baisse de coût ou de latence n’est promise. Les tests injectés vérifient le contrat HTTP ; la validation réelle reste une étape d’intégration distincte.
